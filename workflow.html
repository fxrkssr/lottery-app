2. ⭐ หัวใจของระบบ: เก็บแค่ข้อมูลดิบ

Sheets ไม่เก็บยอดคงเหลือของงวดไหนเลย
ค่าตั้งต้นค่าเดียวคือ initialBalance (ยอดเริ่มต้นก่อนงวดแรก). ยอดเก่า, 72%, คงเหลือ ของทุกงวด คำนวณสดทุกครั้ง ตอน render โดย runningBalance() ที่ไล่ replay จาก initialBalance ผ่านทุกงวดตามลำดับ.
⚠️ ผลที่ตามมา: ถ้าแก้สูตรคำนวณ หรือแก้ข้อมูลดิบงวดใดงวดหนึ่ง → ยอดคงเหลือของงวดนั้น และทุกงวดถัดไป ขยับตามทั้งหมด (ต่อยอดกันเป็นลูกโซ่). ทดสอบโดยดูยอด "คงเหลือ" ของงวดล่าสุดว่าตรงกับความจริงไหม. 
// chain การคำนวณ — ไม่มีตัวเลขไหนถูก cache ลง Sheets
initialBalance
   → calcPeriod(งวด 0) → คงเหลือ  ──┐
                                    ├─ กลายเป็น "ยอดเก่า" ของงวดถัดไป
   → calcPeriod(งวด 1) → คงเหลือ  ──┘
   → ... ไปเรื่อยๆ จนงวดล่าสุด = ยอดคงเหลือปัจจุบัน

4. สูตรคำนวณต่องวด (calcPeriod)

total72     = ผลรวมยอดรับทุกคน × 0.72      // เจ้ามือเก็บ 72%
totalWin    = ผลรวม winTypes               // ตัวถูก ที่ต้องจ่าย
totalDeduct = ค่าแรง + คืน
totalAdd    = เบิก

grandTotal  = ยอดเก่า + total72 + totalAdd
คงเหลือ      = grandTotal − totalWin − totalDeduct
รายการผลต่อยอด
ยอดรับ × 72%+ เพิ่ม
เบิก+ เพิ่ม
ตัวถูก (winTypes)− หัก
ค่าแรง− หัก
คืน− หัก

หมายเหตุ: "อื่นๆ" ในรายการหักถูกเอาออกแล้ว (commit 2d5ed6a). งวดเก่าที่เคยมีค่าพวกนั้นจะถูกคำนวณใหม่ตามกติกาปัจจุบัน.

5. Worker API

Method + Pathหน้าที่
GET /api/dataดึง { settings, periods } ทั้งหมดในครั้งเดียว
POST /api/periodsเพิ่มงวดใหม่ (body = 1 period object)
DELETE /api/periods/:idลบงวดตาม id (frontend ปัจจุบันยังไม่เรียก)
PUT /api/settingsอัปเดต { agents, initialBalance }

Secrets (ตั้งผ่าน wrangler secret put): SERVICE_ACCOUNT_JSON, SPREADSHEET_ID

6. ขั้นตอนตอน "เพิ่มงวดใหม่" (ฝั่ง user)

  1. กรอกชื่องวด เช่น 16 มิย
  2. กรอกยอดรับแต่ละ agent → แอปโชว์ 72% และสรุปสด real-time
  3. กรอกตัวถูก (ถ้ามี) + รายการหัก/เบิก
  4. กด 💾 บันทึก → POST /api/periods → เขียนลง Sheets
  5. ยอดคงเหลือทุกหน้าอัปเดตจากการคำนวณสด (ไม่ได้อ่านยอดที่ save ไว้)
